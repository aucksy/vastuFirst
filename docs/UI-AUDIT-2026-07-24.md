# VastuFirst — UI audit, 24 July 2026 (v0.2.1)

**Trigger:** the owner installed v0.2.1 and reported *"I see many UI issues in this version but I
don't have time to tell you everything."*

**Method:** a full read of all 36 UI files (11 screens + 12 design-system components + theme +
navigation + manifest + build files + CI scripts), plus a mechanical comparison of the implemented
theme against the design contract (`handoff/tokens.json` and the `ramp` / `auditRows` data inside the
Sage & Gold design-system file).

**Verification status.** Items marked ✅ **verified first-hand** were confirmed by reading the exact
file and line myself. The rest come from the systematic sweep and are recorded with their `file:line`
so each can be confirmed as it is fixed. Nothing here has been fixed yet.

---

## The headline

**Nothing in this repository has ever looked at a screen.** CI runs the module-boundary guard, the
token grep, the pure-logic unit tests, and `assembleDebug`. There is no `:app:test`, no Android Lint,
no Compose UI test, no screenshot test, no font-scale or width matrix. The build compiles the UI and
ships it **without ever rendering it**. That is the root cause; every item below is a symptom.

The v0.2.1 audit (`PHASE-3-AUDIT.md`) was a *score / logic / accessibility-labelling* audit. It
concluded "design system is spotless", which was true of what it examined — token discipline really
is clean. It never examined insets, scroll containers, measurement, or layout at 360 dp. That is
where all the damage is.

## P1 — visibly broken

### 1. The guided grid measures to zero height — the primary flow does not work ✅ verified
`app/…/ui/grid/GuidedGridScreen.kt:113-134`

The grid is a `BoxWithConstraints` with `.fillMaxWidth()` and **no `aspectRatio`, no height**. Its
only children are positioned with `Modifier.offset(...)`, which **does not contribute to the parent's
measured size**. So:

- With **no rooms placed** — the state the user lands in every single time — the box measures
  **0 px tall**. The grid is invisible, `drawBehind` draws its lines into a zero-height rect, and the
  tap area is zero. **The user cannot place a single room.** The on-screen instruction "Pick a room,
  then tap the grid" points at nothing.
- Once a room exists, the box is only as tall as the tallest room, and `.clip(shapes.md)` at line 116
  erases anything below it. Rows 2–7 stay permanently unreachable.

Compare `NorthDial.kt:51` and `ZoneMap.kt:71-73`, which both correctly use
`.fillMaxWidth().aspectRatio(1f)`.

**This is almost certainly the largest thing the owner hit.** The sample-plan path bypasses the grid,
which is why scoring still worked.

### 2. No window-inset handling anywhere, with `targetSdk = 35` ✅ verified
`app/…/MainActivity.kt:9-18` — `onCreate` calls `super.onCreate()` and `setContent{}` and nothing
else. No `enableEdgeToEdge()`, no `WindowCompat`, no insets.

A repo-wide search for `statusBarsPadding|navigationBarsPadding|safeDrawingPadding|systemBarsPadding|WindowInsets|Scaffold`
returns **one hit, in a PRD markdown file**. Not one line of implementation.

Android 15 enforces edge-to-edge for `targetSdk = 35` with no opt-out. Every screen root is a bare
`Column`/`Box` with only `.padding(spacing.s6)`. So the status bar overlaps the top of **every**
screen, and the gesture-nav pill overlaps the primary CTA on Welcome, Guided grid, Mark North,
Unlock and Home — on the non-scrolling screens those buttons are **partly unreachable**, not merely
ugly.

### 3. Status-bar icons can be invisible ✅ verified
`AndroidManifest.xml` uses `Theme.DeviceDefault.Light.NoActionBar`; `isAppearanceLightStatusBars` is
never set, and `VastuTheme.kt:129-137` provides `SageGold` unconditionally with no dark variant. On a
phone in system dark mode the system icons go white — on a cream `#F8F6F0` background. Invisible
clock, battery and signal.

### 4. No launcher icon at all ✅ verified
There is **no `res/` directory in the app module**, and the manifest has no `android:icon` or
`android:roundIcon`. The app ships with the **default Android robot icon** on the home screen, in the
launcher, in the app switcher and in the API-31+ splash. There is also no `strings.xml` — the label
is a hardcoded literal in an app that advertises six languages. For a client handover this is the
very first thing seen.

### 5. `GuidedGridScreen` has no scroll container
`GuidedGridScreen.kt:100-102` — root `Column`, no `verticalScroll`. Once the grid is given its proper
square size (~312 dp), the content exceeds a 360 × 800 viewport, and "Next — mark North" at `:185` is
measured off-screen with no way to scroll to it. With the resize tools open or at font scale ≥ 1.3 it
is worse. The user is trapped on the grid.

### 6. Report rows shatter at 360 dp
`ReportScreen.kt:104-111` ✅ structure verified — the `Row` is
`VerdictPill` + `VText(weight(1f))` + `ProvenanceTag`, where **both flanking children are unweighted
and unbounded**. On a 360 dp phone the inner card is ~276 dp; the pill takes 63–92 dp and the
provenance tag 137–166 dp ("Traditional practice", "From classical text"), leaving the room name
2–60 dp. `VText` defaults to `maxLines = MAX_VALUE`, so it does not ellipsise — **it wraps to two or
three characters per line.** This hits the "Already right — leave alone" section of the paid report.

The same pattern, same cause: `ScoreScreen.kt:124-127` (provenance tag clipped off defect cards at
font scale ≥ 1.25), `UnlockScreen.kt:34-37` (the ₹699 row overflows at default font scale on 360 dp),
`GuidedGridScreen.kt:232-237`, `MarkNorthScreen.kt:119-124`.

## P2 — looks wrong or unpolished

7. **Ten controls have no pressed state.** ✅ verified — `foundation/Interaction.kt:24-30` hardcodes
   `indication = null` app-wide, and only `VastuButton`/`VastuButtonInline` draw their own. Chips,
   segmented control, icon buttons, degree steppers, size chips, intent cards, method cards, settings
   rows, plan rows and the settings gear are all **dead to the touch**.
8. **Disabled state exists on two components only** (`Buttons.kt`). `AddHomeScreen.kt:98-111` fakes
   one by changing the title colour while the icon tile and subtitle stay at full strength, so a
   "soon" card reads as live.
9. **Dead controls that look live.** `ReportScreen.kt:85` — the 16-zone toggle has a constant index
   and an empty `onSelect`: tapping does nothing at all. `WelcomeScreen.kt` — the five non-English
   language pills are not clickable and carry no "soon" marker on the pill itself.
10. **Verdict by colour alone.** `ScoreScreen.kt:110` passes `showLabels = false`, which suppresses
    both the room name and the ✓/△/✕ glyph, and there is no legend on that screen — so every room is
    a bare coloured rectangle. `HomeScreen.kt:95` signals the score band by number colour only.
    Directly contradicts the review gate and §2 of `UI-POLISH.md`.
11. **Two more screens with no scroll container** — `UnlockScreen.kt:29-31` and
    `SettingsScreen.kt:46-48`. Both overflow at raised font scale, taking the CTA with them.
12. **Grid lines are 1 physical pixel, not 1 dp.** `GuidedGridScreen.kt:122-123` — `strokeWidth = 1f`
    inside a `DrawScope` is 0.33 dp on a 3× phone. Invisible. The token grep cannot see raw floats in
    a draw scope, which is exactly how it survived.
13. **Room labels overlap and spill.** `ZoneMap.kt:121-148` draws text with no clipping, no ellipsis
    and no fit check; the two baselines are 8 units apart at 12 sp, so they overlap at font scale ≥1.5.
14. **The dial and slider are unusable with TalkBack.** `NorthDial.kt:61-70` has no semantics at all;
    `Slider.kt:86-89` sets `progressBarRangeInfo` but no `setProgress` action, so it announces as
    read-only. The only non-visual route to setting North is the ▲▼ stepper at 1° per tap.
15. **Canvas model rebuilt every frame.** `MarkNorthScreen.kt:50` and `ScoreScreen.kt:89` call
    `buildZoneMapModel(...)` with no `remember`, and `ZoneMap.kt:145-147` measures ~23 strings inside
    the draw scope against a default 8-entry cache. Dragging North will visibly stutter.
16. **Palette scroll resets.** `GuidedGridScreen.kt:170` creates its scroll state inside a `when`
    branch that is torn down on every room placement.
17. **`HomeScreen` flashes "No plans yet"** on every cold start (`HomeViewModel.kt:14-15` seeds
    `emptyList()`; there is no loading state).
18. **A loading state that can never resolve.** `ScoreScreen.kt:62-68` shows "Reading your home…"
    whenever `analysis == null`; `NewPlanViewModel.kt:143` silently does nothing if the row is
    missing. No timeout, no error branch, no back button — an unescapable screen.
19. **Dead ends.** `ReportScreen` takes no navigation callbacks at all — after paying, the only way
    out is five system-back presses. `UnlockScreen` is a paywall with no visible cancel.
20. **No click debounce anywhere** — double-tapping any CTA pushes two destinations
    (`VastuNav.kt`, 13 bare `navigate(...)` calls). Score → Fix → North → Score grows the back stack
    without bound.

## Design-contract drift (mechanically detected)

Run: `node scripts/check-design-fidelity.mjs`

| Drift | Design | Code | Verdict |
|---|---|---|---|
| `border-hairline` | 1 dp | `0.6.dp` (`VastuTheme.kt:78`) | **real drift — fix** |
| letter-spacing on `h3`, `label`, `caption`, `mono` | `.005em / .01em / .02em / .02em` | never set in `VastuTypography.kt` | **real drift — fix** |
| `label` weight | 600 | 500 | **accepted** — bundled DM Sans has no 600 cut; never faux-bold |
| `radius-full` | 999 | `percent = 50` | **accepted** — equivalent for a pill |

**Contrast:** all six body-text pairs pass their 4.5:1 floor. Three accent colours sit below 3:1 —
`secondary` 2.24:1, `score-workable` 2.55:1, `zone-e` 2.08:1 — which the design itself marks as
"accent". They are not palette bugs; they are a **usage constraint**: those three may never carry a
meaning on their own. Item 10 above violates exactly that constraint.

## What CI verifies today, precisely

**Does:** module boundaries (engine/rules/shared/data Android-free) · the token grep (raw
`Color(0x`, `N.dp`, `N.sp` outside the theme package — genuinely clean) · pure-logic unit tests ·
`assembleDebug` compiles.

**Does not:** anything a user can see. No `:app:test`, no `:designsystem:test`, no Android Lint (which
alone would have flagged the missing launcher icon), no Compose UI tests, no screenshot tests, no
360 dp or font-scale matrix, no inset check, no touch-target check, no `contentDescription` check.

The token grep also has three blind spots that matter: raw floats inside a `DrawScope` (how the
1-pixel grid line survived), `Color.*` named constants, and raw alpha literals. Plus a latent shell
bug — `for f in $files` word-splits on spaces, which under `set -euo pipefail` would abort the script
rather than report a violation.

## Fix order proposed for 4 August

1. **Insets + edge-to-edge + status-bar icon colour** (items 2, 3) — one helper, applied at all 11
   screen roots.
2. **The guided grid**: `aspectRatio(1f)`, root `verticalScroll`, dp-based stroke (items 1, 5, 12).
3. **Launcher icon, adaptive icon, `strings.xml`, splash background** (item 4).
4. **Row shatter**: weight/ellipsis/`FlowRow` at the five sites (item 6).
5. **Pressed state for all controls** — one owned indication in `clickableTap` fixes ten at once
   (item 7).
6. **Scroll containers** on Unlock and Settings; hoist the palette scroll state; `remember` the zone
   map model (items 11, 16, 15).
7. **Exits and debounce**: back affordances on Report/Unlock/Score, a navigation debounce (19, 20).
8. **Colour-alone**: labels/glyph on the score zone map and a band word on saved plans (item 10).
9. Design-contract drift: hairline width and letter-spacing.
10. P3 sweep.
